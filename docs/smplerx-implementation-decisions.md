# SMPLer-X 实施取舍与代价

软件迁移已经验证。真实相机遮挡和动作质量尚未验收，工程性能目标未达到。
具体证据见 [验证记录](smplerx-migration-verification.json) 和 [性能记录](smplerx-s32-endurance.json)。

1. 跳过上游训练/评估数据集导入，直接建立相同的官方推理图并转换检查点键。
   风险是上游版本变化可能改变图或权重。固定了源码版本、资产 hash，检查缺失学习参数，并对照真实子进程数值。
2. torchgeometry 0.1.2 的布尔减法在内存中替换为布尔取反。
   风险是旋转转换改变。恒等和 90 度测试、真实人体模型 FK 对照已通过，安装包没有被修改。
3. 早期首帧冻结体型方案已被替换。现在取五个稳定系数预测的中位数并固定。
   代价是启动需要更多样本；稳定阈值是工程设置，不是模型置信度。
4. 使用共用 `apply_camera_arm_frame` 和几何测量函数，删除未接入的薄 `CameraArmPipeline` 框架。
   风险是入口的时间或配置仍可能不同。增加了不规则采集时间、同记录回放和真实入口检查。
5. 原始视频以逐样本无损 RGB 存在 H5，不另存需同步的有损 MP4。
   代价是内存和磁盘占用更大；当前录制器在保存前保留本次数据。
6. 保留原有 IK 数值算法及显式腕姿态安全策略。旧测试改为验证姿态尝试、拒绝保持和状态恢复。
   代价是更换人体模型不会自动解决 IK 的可达性和误差。VR 数值实现未改变；Mock 明确声明 AVP 来源。
7. 多人、检测框明显换位或离场超过两秒要求新会话和重新标定。
   代价是有效操作者也可能被保守地保持；该策略不宣称提供身份识别。
8. 姿态映射使用测得的机器人臂长检查可达范围，位移映射继续检查原行程框。
   若错误使用旧行程框，会误报合法的姿态目标。新增测试同时验证合法姿态通过和不可达目标失败；未修改安全阈值。

独立审查发现的异步腕标定、丢失恢复和时间一致性问题均已通过失败测试复现后修复。
作者另修复无手指回放和诊断模式不匹配。最终完整回归 560 项，0 失败，3 跳过；
dex 独立环境补测 3 项通过。没有延后处理的审查 Minor 项。

工作保留在当前本地分支。没有推送、合并，也没有删除用户的旧录制或许可模型。
