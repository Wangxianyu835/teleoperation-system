# 视频手部输入的尺度问题与改进建议

更新日期：2026-10-09。本文记录当日对当前工程、训练产物及本地 TransHandR 原项目的检查结果。属于问题诊断和实施建议，尚未实现 world landmarks 迁移、尺度标定或损失重设计。

## 1. 当前结论

当前训练的主要问题是：MediaPipe 图像归一化关键点与机器人米制 FK 坐标直接参与绝对距离损失，尺度不具有可比性；指尖距离项又通过 `×1000` 和平方误差放大，几乎主导总损失。

原版 TransHandR 还存在一个影响比较的重要差异：其指尖距离损失在默认 MSE 已求 batch 均值后，再除以一次 batch size。当前工程取消了这次重复平均，因此即使保留相同的损失权重，其有效强度也与原版不同。

改用 MediaPipe `hand_world_landmarks` 可以改善单位和三维几何表达，但不会自动解决人手与机器人尺寸、骨骼比例和可达范围的差异。推荐先采用 world landmarks、固定掌部尺寸标定和一致的数据契约，再重新评估损失权重及实际手势效果。

随机种子不是上述问题的原因。当前默认种子为 `1234`，训练开始时设置一次；每轮训练样本仍会重新打乱，参数正常更新。

## 3. 当前损失为什么会放大

`src/teleoperation/learning/losses.py` 中，7 对指尖距离分别执行：

```python
source_distance = norm(source_tip_a - source_tip_b) * 1000.0
robot_distance = norm(robot_tip_a - robot_tip_b) * 1000.0
pair_loss = MSE(source_distance, robot_distance)
# 对 7 对求均值，再乘配置权重 10
```

如果距离数值差为 `0.2`，对应加权平方误差为 `(0.2 * 1000) ** 2 * 10 = 400000`。这只是量级示例，不是对全部样本的重新计算。

当两边都是米时，乘 1000 可以解释为转换到毫米，但 MSE 数值会相应增大一百万倍，权重必须按该单位重新设计。当前人手侧不是米，同时乘 1000 无法使单位一致。

机器人关节角可以改变指尖位置，却不能改变骨段长度。尺度不匹配可能使距离目标难以达到，并诱导模型牺牲方向或角度拟合。该机制与平台期相符；是否发生关节饱和或姿态塌缩仍待预测结果验证。

## 4. 原版 TransHandR 的设计与差异

检查对象：本地 `D:/2026/code/TransHandR/TransHandR` 的当前代码，不代表该项目全部历史版本。

### 4.1 固定缩放

`config/variables_define.py` 默认选择 `visionpro` 和 `linker`：

```python
scaling_factor = 1.0
scaling_factor_rb = 1.0
```

人手在 `dataset/custom_dataset.py` 读取后乘固定系数；机器人在 `model/angle2real.py` 的 FK 输出上乘固定系数。Vision Pro 采集代码直接提取手部变换矩阵的平移分量，与图像归一化 landmarks 的来源不同。原版 `glove_data_aligned.h5` 中右手腕到中指指尖的距离中位数约 0.184，处于不同于当前视频输入的数值尺度。

配置曾预留 `1/0.061`（人手）、`1/0.064`（L21）的注释写法，但默认未启用；附近代码没有明确说明这些长度对应的骨骼部位，不能直接照搬。其他数据源或机器人分支使用不同固定系数，也不是逐帧自适应标定。

原版向量和指尖方向项做单位向量归一化，角度项比较角度；拇指平面距离、指尖间距离仍依赖绝对尺度。拇指平面距离还对机器人侧使用 `0.9` 系数。

### 4.2 重复平均改变了有效权重

原版 `model/loss.py::tip_distance_loss`：

```python
return total_loss / (batch_size * len(tip_pairs))
```

当前工程：

```python
return total_loss / len(pairs)
```

原版 `main_train.py` 使用默认 `nn.MSELoss()`，本身已经对 batch 求均值。因此在相同批次、预测和权重下，当前该项是原版的 `batch_size` 倍。原版默认 batch size 为 1024；当前为 64。该倍数描述同批次下的公式差异，不表示两次不同实验的总损失必然相差 1024 或 64 倍。

不能将恢复重复平均作为修复方案。它使损失依赖 batch 大小和尾批大小；应保留清晰的均值定义，显式设置权重。原版较小的总损失不能直接证明姿态更好。

## 5. world landmarks 能解决什么

根据 [MediaPipe 官方 Hand Landmarker Python 文档](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python)：图像 landmarks 的 x、y 分别按图像宽、高归一化，z 与 x 大致同尺度；world landmarks 是以米表示的三维坐标，原点在手的几何中心。

因此 world landmarks 更适合与 URDF 米制 FK 比较，也避免把图像归一化 xyz 直接当作物理欧氏空间。工程上仍应将其视为模型估计，实测尺寸稳定性，不把“单位为米”当作绝对测量精度保证。

- 继续减去手腕点，再进行掌心方向对齐。
- 不把 world landmarks 当作机器人基座坐标中的绝对手部位置。
- 仍需处理人手和机器人尺寸、手指比例、自由度及可达范围差异。
- 旧 normalized 关键点 H5 无法精确恢复对应 world landmarks；有原视频可重新推理，否则需重新录制。

## 6. 可行方案与实施顺序

### 6.1 推荐基线：world landmarks + 固定掌部尺度

针对手势比例模仿，建议保持机器人 FK 为真实尺寸（`robot_scale=1`），只将人手映射到机器人参考尺寸。若任务要求保留实际夹持开口，则应另行选择物理距离目标，不能默认套用比例模仿。

标定流程：

1. 左右手分别录制约 3～5 秒清晰、自然展开的 world landmarks，筛掉缺失、遮挡和异常帧。
2. 选择稳定掌部参考，例如食指 MCP 到小指 MCP。MediaPipe 21 点索引为 `5,17`，项目 25 点索引为 `6,21`。
3. 人手参考长度 `L_h = median_t(norm(p_5(t) - p_17(t)))`。
4. 机器人参考长度 `L_r` 从参考姿态 FK 获取。当前候选对应点为索引 `1,10`，须先核对其 URDF 几何含义，确认关节中心对应合理。
5. 固定系数 `s = L_r / L_h`；对手腕相对坐标进行方向对齐和统一缩放。
6. 同一用户、手侧、标定版本在训练与推理中复用相同系数。新用户重新标定；系数不逐帧跳变。

此方案是工程基线，不保证所有手指同时精确匹配。不要直接用跨姿态的腕到指尖距离或两个数据集的中位数之比标定。

### 6.2 同步迁移数据契约与实时链路

不能只替换输入数组。至少检查这些位置：

| 位置 | 需要的处理 |
|---|---|
| `src/teleoperation/inputs/mediapipe.py` | 按同一次结果和手索引读取 world landmarks；图像 landmarks 保留给画面显示及需要图像位置的身份跟踪逻辑 |
| `src/teleoperation/data/hand_recording.py` | 保存真实来源、单位、坐标版本；建议同时保存图像与 world 数据，便于诊断 |
| `src/teleoperation/data/hand_h5.py` | 扩展来源校验，明确拒绝不兼容输入，不静默混用 |
| `src/teleoperation/contracts/coordinates.py` | 为新来源和尺度映射建立明确版本，避免沿用固定的 normalized 标签 |
| `src/teleoperation/applications/hand_processing.py` | 更新来源分支及校验，保证对齐和缩放只执行一次 |
| dataset、checkpoint、predictor、export/realtime | 保存并验证输入空间、缩放系数、标定方法和版本，确保离线与实时一致 |

建议新增元数据包括 `source_landmark_space`、`length_unit`、`scale_mapping_version`、`source_scale`、`calibration_id`、`hand_side`。具体字段属于待实现设计，不是当前已支持接口。

world 坐标以手为中心，不应直接替代原来用于图像位置关联的坐标；跟踪阈值也要检查单位。旧 checkpoint 不应直接视为兼容新输入，基线优先重新训练；若研究权重迁移，需单独验证。

### 6.3 重新设计距离项的有效权重

- 保留每项明确、与 batch 大小无关的均值定义。
- 统一使用米或明确的参考长度比例，写清距离损失的单位；毫米制也可以，但须匹配权重。
- 先记录未加权值、加权值和各项梯度贡献，再确定权重，不能仅令所有损失数值相等。
- 可通过短实验比较方向/角度基线、加入距离项、加入捏合约束的效果；临时关闭距离项只用于定位，不代表最终无需距离约束。
- 将六项训练和验证损失加入 CSV，避免总损失掩盖单项支配。

### 6.4 全局缩放不足时的后续方案

- 用多段可靠的掌部距离拟合一个固定尺度，降低单个参考点的影响；先核对人机关键点对应。
- 使用各自固定参考长度归一化后的指尖距离，让目标成为相对开合程度。
- 若指长比例仍造成明显误差，按机器人骨段长度构造方向目标，或组合方向、关节角、捏合接触和可达性约束。
- 若任务依赖准确物理距离，用实测参考长度、深度信息或其他标定手段验证 world 坐标尺度；再决定是否保留 1:1 物理距离。

上述方案应逐步对照，不同时堆叠后只看总损失。

## 7. 不可行或不应作为修复的做法

| 做法 | 为什么不能解决当前问题 |
|---|---|
| 换随机种子、单纯增加轮数或降低学习率 | 不能修正输入单位、目标可达性或损失定义 |
| normalized xyz 统一乘一个猜测常数，称为 world 坐标 | 无法精确恢复物理三维几何，x/y 的归一化方式也不同 |
| 两边都乘 1000，认为单位已经一致 | 同倍放大不消除原有单位差异 |
| 只删除 `×1000` 并以损失变小作为成功 | 数值降低不证明尺度或手势正确；单位调整必须与权重及效果验证配套 |
| 恢复原版重复除以 batch size | 掩盖有效权重，使行为依赖 batch/尾批大小 |
| 直接照搬 `1/0.061`、`1/0.064` | 参考长度来源未确认，且数据源不同 |
| 每帧按腕到指尖距离归一化 | 握拳等动作改变该距离，会把姿态变化误当成尺度变化 |
| 每帧按所有坐标最大值或包围盒大小归一化 | 对姿态、离群点敏感，可能产生缩放抖动 |
| 只换 world 数组，继续标记 normalized | 数据来源失真，校验、跟踪及模型输入可能不兼容 |
| 训练用新尺度、推理仍用旧尺度 | 产生输入分布不一致，离线效果不能迁移到实时 |
| 用一个全局系数要求所有人机骨段完全重合 | 人机骨骼比例和自由度不同，整体缩放无法消除局部差异 |
| 只比较新旧总损失，判断哪个模型更好 | 数据、手侧、单位和归约方式不同，数值不直接可比 |

## 8. 验证标准与未决事项

建议先用短实验验证链路，再进行完整训练：

1. **数据正确性**：world 数据、米制单位、手侧和版本一致；无非有限点；缺失处理明确；缩放只做一次。
2. **尺度稳定性**：同一手势在相机前后移动、适度转动时，记录掌宽和骨段长度的中位数、分位数及相对波动。阈值应由实际设备基线确定，不预设未经验证的通用值。
3. **几何合理性**：叠加参考骨架，检查 MCP 对应、掌心方向、左右手处理及可达范围。
4. **优化行为**：检查分项损失与梯度、关节极限占比，不只看总损失。
5. **动作效果**：固定测试张手、握拳、拇指对食指/中指/无名指/小指捏合，检查接触、穿透、抖动和延迟。
6. **公平对照**：使用相同测试动作与明确的物理/相对误差指标。按录制片段或会话留出验证集，使各类手势都有合理覆盖；不要随机拆分高度重叠的相邻窗口造成泄漏。
7. **离线实时一致性**：同一输入经录制回放与实时处理得到一致的模型输入，模型与标定元数据可追溯。

仍待验证：实际 world landmarks 的质量和稳定性、机器人掌部参考点是否合适、左右手标定系数、距离项合理权重、当前模型是否出现关节饱和或姿态塌缩。已有证据确认尺度契约与损失归约差异，不足以将所有效果问题都归因于单一因素。
