# 素材来源与展示说明

本成果包的日期为 2026-10-07，代码基准为 `c57c165`。展示文件全部保存在本目录中，文档、图片和视频可独立复制；原始数据、权重与仿真模型不随成果包重复打包。

## 1. 数据来源与保护

手部素材读取项目本机 `outputs/hand_retargeting/palm_angles.h5`，原始关键点文件由该角度文件的 `input_file` 元数据定位：`palm_local_visual_hand_data_20261005_002654.h5`。其坐标模式为 `palm_local_to_l21_v1`，有 6515 帧。角度元数据记录历史 `palm_local_v2/model_best.pth` 权重位置。

本轮读取的是已有真实记录的**关键点与预测角度**，没有提供原始摄像头画面，也没有重新采集真实设备。图像中的机器人是 URDF 渲染，骨架是数值投影，没有使用 AI 生成图片替代实验画面。

生成脚本验证两份 H5 的坐标声明、帧编号和时间戳相等，以及选定区间全部有效。角度、输入 H5 和历史 checkpoint 的 SHA-256 在运行前后核对一致。原始路径、哈希、角度元数据、软件版本与各输出文件哈希记录在 [素材元数据](素材元数据.json)。绝对路径仅用于描述原始本机来源，阅读成果包无需这些路径。

### 视频区间与时间轴

| 侧别 | 零基帧索引区间 | 有效帧 | 原记录起始时间 | 区间首尾时间跨度 | 输出 |
|---|---|---:|---:|---:|---|
| 左手 | `[2640,2940)` | 300 / 300 | 94.975 s | 9.955 s | 150 帧 / 15 fps / 10 s |
| 右手 | `[3465,3765)` | 300 / 300 | 122.461 s | 9.990 s | 150 帧 / 15 fps / 10 s |

## 2. 渲染方法与解释边界

- 机器人渲染使用 PyBullet `DIRECT` + `ER_TINY_RENDERER`。生成脚本通过 `L21HandAngles.native_mapping_dofs()` 显式切除 18D 的占位维并保留原 dtype，再由 `NativeHandAdapter(..., limit_mode='clamp')` 按原生关节名称映射。
- 通过 `resetJointState` 直接设置目标角度，没有执行 motor 跟踪、接触任务或物理积分。视频含有时间变化，但呈现的是目标姿态序列。
- 未使用角度缩放、动作幅度放大、平滑、坏帧修复、数据插值或重新训练。原生限位裁剪按现有实现执行，视频标出每帧裁剪的关节数。
- 三机器人视频只驱动所示一侧的手指；其余手、手臂、腰腿保持各机器人原有中性姿态。全机缩略图用于说明机器人和手的位置。
- 手部相机按片段中的手指包围盒固定取景；左右手以蓝／橙色显示，颜色和相机只改变展示。
- 人手关键点和预测 FK 用同一侧 L21 参考掌面基变换后，正交投影至掌面 xy 平面。两面板保持各自固定显示尺度，不用于直接读取厘米误差。
- 预测 FK 使用已有 L21 URDF 与 `L21.training.robot_scale` 计算；第 0 维为占位，5 个 tips 为固定节点。
- 部分姿态中的输入与预测差异、拇指运动不足仍保留。动图不是精度、真实设备接入、物理跟踪或任务成功的验收证明。

## 4. 视频、动图与兼容性

四个文件基名为 `left_comparison`、`right_comparison`、`three_robots_left`、`three_robots_right`。每个基名对应 MP4、GIF 和 `_poster.jpg` 封面。

本次四段 MP4 实际编码均为 **H.264 / avc1**，由 OpenCV 的 **MSMF（Microsoft Media Foundation）** 后端完成；视频读取验证得到 `h264`，MP4 含 `avc1` sample entry。OpenCV 的 FFmpeg 后端尝试 OpenH264 时打印版本错误，但 MSMF 成功写出 H.264，不能把单个后端报错解释为最终导出失败。本机未发现可调用的 ffmpeg 可执行文件。

MP4 为 1280×720、15 fps、10 秒，无音轨；GIF 为 640×360、5 fps、约 10 秒。GIF 调色与低帧率只影响预览显示，MP4 保留 150 个导出帧。生成脚本优先 H.264，其他环境若不支持则回退到 mp4v，实际结果以元数据为准。

[离线展示页](index.html) 同时提供 MP4 与可折叠 GIF，默认展开动图。MP4 可用浏览器、本地播放器打开，或导入支持 H.264 的演示软件。正式答辩前请在目标电脑预演播放。

## 6. 重新生成

使用正式 `teleoperation` 环境，在原项目根目录安装当前包后执行：

```powershell
python -m pip install -e . --no-deps
python -B present/build_materials.py --phase all
python -B present/verify_materials.py
```

生成脚本使用 `src/teleoperation` 的正式接口，不再使用旧包或修改 `sys.path`。无需重新生成既有素材来完成这次入口修复；上面的命令供后续手动复现使用。

只生成图片、视频或检查视频时，分别使用 `--phase images`、`--phase videos`、`--phase verify`。自定义输入时可使用 `--angles <角度H5>`、`--source <对齐关键点H5>`；需要满足对应帧编号、时间戳和固定帧区间要求。其他平台可用 `--font <中文字体文件>`。

生成依赖 PyBullet、Torch、NumPy、h5py、Pillow、OpenCV 及仓库模块。脚本只从已有角度计算 FK 和映射，不加载权重重新推理，但保留对历史 checkpoint 的哈希验证，因此原始权重路径仍需可读。本机的软件版本记录在元数据中。

图像先生成，视频帧逐帧写入 MP4；GIF 只缓存降采样缩略帧。生成不调用默认 recorder，不启动真实相机或控制硬件。`qa/` 和构建日志用于本机检查，不进入版本控制。
